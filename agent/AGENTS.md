# 全局工作约定

## 语言与风格

- 默认使用自然、地道、简洁的中文回答；代码、命令、日志、标识符保持原文。
- 优先引用原文而非转述，提出观点尽可能附上例子或代码。
- 用户的表述过于宽泛或涉及决策时请积极询问用户。
- 文档与代码注释描述当前状态，不记录历史修改记录，不把实现猜测写成确定规则。

## 行为边界

- ✅ **Always**：
  - 进入具体项目（`~/ws/*`）时，优先检查并遵守项目内的 `AGENTS.md` 或 `README.md`。
  - 临时文件一律进 `/tmp/pi/`，用完即删；项目文件一律进 `~/ws`，家目录直下不留脏文件。
  - 完成任务时执行「自省交代」。
- ⚠️ **Ask first**：
  - `git commit`、`git push`：仅在用户明示后执行；提交前先跑 `git status` 汇报。
  - 其他关键与破坏性命令：`git reset --hard/clean/rebase`、`gh pr create/merge/close`、`gh release`。
  - 修改非当前任务范围内的文件、引入新架构依赖、改动数据库 Schema。
  - 处于 ssh remote 状态时，任何涉及 remote 目录或配置的改动。
- 🚫 **Never**：
  - 将密钥、Token、Cookie 等机密写进文件、代码、日志或 CLI 参数。
  - 为了“测试全绿”而删除、注释或弱化既有测试断言。

## 常用命令

- 检索：`rg PATTERN`；找文件：`fd NAME`；看目录：`eza --tree -L2`；JSON：`jq`。
- OCR / PDF 转 markdown 用本机 PaddleOCR-VL（`~/PaddleOCR`，用法见其 `README.md`）

## 压缩记忆检索

- 压缩记忆中的 `[12位十六进制id]` 可用 `recall(<id>)` 取回原文。需要精确命令、报错、路径、数值、用户原话，或据某条结论改代码 / 下判断时，先 `recall` 再行动。

## 任务交付与自省交代

阶段完成或汇报进度时，不能只说“已完成/测试全绿”，须交代以下四项：

- 验证: <实际执行的命令> → <结果与覆盖的核心断言>
- 盲区: <未覆盖的边界、异常链路、并发、真实外部依赖>
- 假设: <未经用户明示的取舍：默认参数、范围裁剪、降级方案>
- 副作用: <对上下游模块、接口契约、性能的可能波及>


## Git

- 提交信息用 `英文动词: ...` 开头如 `Fix: 修复了一个 bug`，一次提交只做一件事。

## 飞书通知

- 长时间任务（构建/测试/批量处理）结束、中途失败、或需要离席决策时：`notify(action="send", adapter="ops", text="…")`。
- 格式：「结论 + 关键证据（命令/耗时/结果）+ 待用户确认事项」。用户正在实时交互或超短任务不发。
